## 2. 측정 스크립트를 고친 내용과 근거

고치기 전 첫 실행(v1 경로)에서는 A9가 F였다. 원인은 사례의 전제 두 가지가 현재 설계와 맞지 않아서였다.

1. **v1 경로를 재고 있었다.** 스크립트의 격리 승인 폴더에는 v2 표식이 없어 hook이 v1로 동작했다. 실제 승인 저장소는 2026-11-14에 v2로 전환됐다. → 격리 폴더를 시작할 때 v2로 전환한다(`approvals.Store.admin_activate`, `tests/test_approvals.py:840`과 같은 방법). 승인 호출에는 계획 파일 경로(`filePath`)를 넣는다.
2. **blocked 상태를 hook이 볼 기회가 없었다.** 사례는 파일을 blocked로 썼다가 곧바로 in-progress로 되돌렸다. 폐기는 hook이 그 상태를 봤을 때 일어난다(`hooks/approvals.py:271-273`, 같은 절차의 게이트 테스트 `tests/test_approvals.py` T1은 중간에 프롬프트를 한 번 보낸다). → 두 쓰기 사이에 프롬프트를 한 번 보낸다.
3. 위 변경으로 A9에서 widget 승인이 폐기되므로, 뒤따르는 N1~N4 앞에서 두 계획을 다시 승인한다. v2에서는 폐기된 승인이 되살아나지 않고 다시 승인하면 새 승인이 발급되는 것이 설계다(P0-04 계획 T7).

남는 한계(결함으로 기록): **hook이 한 번도 실행되지 않는 사이에 계획을 blocked로 돌렸다가 되돌리면 옛 승인은 폐기되지 않는다.** 계획 해시는 frontmatter를 빼고 계산하므로 흔적이 남지 않는다. 세션이 열려 있지 않은 동안 사용자가 파일을 직접 고친 경우에만 해당한다.

## 5. 되돌리기 리허설

세션 임시 폴더에 만든 사본(`git clone`) 두 개에서만 했고 끝난 뒤 지웠다. 실제 저장소에서는 revert, reset, checkout을 하지 않았다.

| 리허설 | 방법 | 결과 |
|---|---|---|
| (가) 마지막 작업 | P0-13 코드 커밋 `06be77f`를 `git revert --no-commit` | 충돌 없음. `ruff check` 통과, `tests/test_handoff.py` FAILURES 0 |
| (나) 전체 | 기준선 태그 `devenv-baseline-2026-11-11` 뒤 62개 커밋을 `git revert --no-commit` | 충돌 없음. `git diff --quiet <태그>` 종료 코드 0(파일 내용이 태그와 같음) |

확인하지 않은 것:
- 되돌린 상태에서의 전체 게이트.
- 저장소 밖 상태의 되돌리기: v2 승인 저장소는 한 번 전환하면 v1으로 돌아가지 않는 설계이고(표식만 지워도 v2로 본다), `~/.claude/state/handoff`의 기록과 임시 폴더의 세션 상태는 커밋을 되돌려도 남는다. 코드를 P0-04 이전으로 되돌리면 v1 경로가 다시 동작하는데, 그때 v2 저장소의 승인은 쓰이지 않는다(`tests/test_approvals.py:1365` 부근의 사례가 이 동작을 다룬다).
