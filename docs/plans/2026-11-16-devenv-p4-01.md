## Context
skill·subagent·MCP가 실제로 쓰이는지, hook의 관측 기록(위험 점수, 테스트 누락, 리뷰 없음, 큰 출력, 실패 종류)이 얼마나 쌓였는지를 읽는 방법이 없다. P4 계획의 사용 실태 표는 일회용 스크립트로 센 것이다. P4의 다른 항목들은 "고친 뒤에 사용이 늘었는가", "안내가 소음인가", "강제로 바꿔도 되는가"를 이 숫자로 판단하므로 먼저 만든다.

## 확인한 사실
- 대화 기록: `~/.claude/projects/<폴더>/*.jsonl`, 한 줄이 JSON 한 건. 도구 호출은 `message.content[]`의 `type: "tool_use"` 블록(`name`, `input`)이다. Skill은 `input.skill`, subagent는 `Agent`/`Task`의 `input.subagent_type`, MCP 도구는 이름이 `mcp__<서버>__<도구>`다(오늘의 일회용 집계에서 확인: 세션 11개, Skill 3회, Agent 95회, MCP 18회).
- 관측 기록(승인 폴더 `~/.claude/discipline/`, 격리 시 `CLAUDE_DISCIPLINE_HOME`): `review-observe.jsonl`(`at, state, rules, gate`, `hooks/discipline.py:3312`), `test-gap-observe.jsonl`(`at, files`), `output-size-observe.jsonl`(`at, chars, test, failed, who`, `discipline.py:977`), `risk-observe.jsonl`(`at, score, kinds, files, lines, repos, advised`), `authz-observe.jsonl`(이미 `hooks/authz_report.py`가 센다).
- 실패 종류 기록: `~/.claude/state/failures/*.jsonl`(`at, source, kind, session`, `hooks/recurrence.py`).
- **승인 폴더는 에이전트의 도구로 읽지 않는 곳이다**(`hooks/authz_report.py:6` "the user runs this in their own terminal"). 그 선례를 따른다: 관측 기록 부분은 사용자가 자기 터미널에서 실행하고, 나는 예시 입력으로만 검증한다.

## 대안 비교
| 선택지 | 내용 | 판단 |
|---|---|---|
| A. 명령 하나, 하위 명령 둘(추천) | `usage_report.py calls`(대화 기록, 에이전트도 실행 가능)와 `usage_report.py observe`(관측 기록, 사용자가 실행) | 읽는 곳의 접근 규칙이 달라 나누는 것이 맞다. 출력 형식은 같게 둔다 |
| B. `authz_report.py`를 넓힌다 | 기존 도구에 나머지 기록을 더한다 | 그 도구는 테스트와 문서가 "승인 관측 전용"으로 묶여 있다. 대화 기록 집계와 성격이 다르다 |
| C. 세션 종료 hook에서 자동 집계 | 매 세션 끝에 요약 파일을 쓴다 | hook 지연과 쓰기가 늘고, 필요할 때만 보면 되는 숫자다 |

## 설계
`hooks/usage_report.py`(hook으로 등록하지 않는다):

    python -I hooks/usage_report.py calls   [--since YYYY-MM-DD] [--projects DIR]
    python -I hooks/usage_report.py observe [--since YYYY-MM-DD] [--home DIR] [--failures DIR]

- 순수 함수
  - `count_calls(lines) -> Calls`: 한 세션 파일의 줄들에서 skill·subagent·MCP 서버·MCP 도구·그 밖의 도구 이름별 횟수. 깨진 줄은 건너뛰고 센다.
  - `summarize_rows(kind, rows, since) -> list[str]`: 관측 기록 한 종류의 요약 줄들. 종류별 요약:
    - risk: 건수, 점수의 최솟값·중앙값·90번째 백분위·최댓값, 기준 이상 건수와 안내 건수, 종류별 파일 수.
    - test-gap: 건수, 파일 수 합.
    - review: 상태별 건수, 게이트가 켜진 건수.
    - output-size: 건수, 테스트 실행 건수, 주 대화/subagent, 글자 수의 중앙값·최댓값, 기준(8,000자) 초과 건수.
    - failures: source×kind별 건수, 세션 수.
  - `percentile(values, q)`: 정렬된 값의 가장 가까운 순위.
- I/O
  - `calls`: `--projects`(기본 `~/.claude/projects`) 아래 `*/*.jsonl` 중 수정 시각이 `--since`(기본 30일 전) 이후인 것을 한 번씩 읽는다. 폴더 이름에 `quant`나 `qr-`가 든 것은 건너뛰고 그 수를 출력한다(범위 밖). 출력: 세션 수, Skill·Agent·MCP 호출이 있던 세션 수, 이름별 횟수 표. **쓰이지 않은 것도 보이게** 설치된 자체 skill(`skills/*/SKILL.md`)과 subagent(`agents/*.md`) 이름을 0과 함께 넣는다.
  - `observe`: `--home`(기본: 승인 폴더)의 관측 파일 네 개와 `--failures`(기본 `~/.claude/state/failures`)를 읽는다. 없는 파일은 "기록 없음". 파일당 끝의 4MB까지만 읽는다.
- 출력은 이름·숫자·날짜뿐이다. 프롬프트, 명령, 경로, 파일 이름, 도구 입력은 읽지도 출력하지도 않는다(도구 이름과 `input.skill`, `input.subagent_type`만 본다). skill·agent 이름은 대화에서 온 글자이므로 `[A-Za-z0-9:_.-]` 60자까지만 받아 그 밖은 `(other)`로 묶는다.
- 종료 코드: 0 정상(기록이 없어도), 2 잘못된 입력.

`hooks/retention.md`에는 손대지 않는다(쌓이는 것이 늘지 않는다).
