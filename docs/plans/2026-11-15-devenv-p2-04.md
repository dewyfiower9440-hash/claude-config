# devenv P2-04: 실패 재발 감지와 Gotchas 후보 안내 (관측과 제안만)

- 승인 근거: 사용자 지시 2026-11-15 "개발환경 고도화 작업 이어서 계속해"(상시 승인)

## Context
같은 종류의 함정(인코딩, 환경·설치, 시간 초과)이 세션을 넘어 반복돼도 지금은 알 길이 없다. Gotchas는 그때 기억나면 손으로 적는다. 이 항목은 실패의 **종류**를 저장소별로 세어 두고, 같은 종류가 여러 세션에서 반복되면 다음 세션 시작 때 "Gotchas 후보"로 한 줄 알린다. CLAUDE.md에는 아무것도 쓰지 않는다(마스터 계획: "메모리나 Gotchas를 전역 규칙에 자동 반영하지 않습니다").

## 확인한 사실
- CI 실패의 종류는 이미 분류된다: `ci_status.classify_failure(step, conclusion, log_tail)`이 `timeout | encoding | environment | lint | test | other`를 준다(`hooks/ci_status.py:187`). 실패한 run의 종류는 `state["ci"][top]["kind"]`에 들어간다(`ci_status.py:391`).
- 게이트 실패는 `record_evidence`가 `outcome: "failed"`, `kind: "gate"`로 남긴다(`hooks/verification.py:272`, `hooks/discipline.py:2022` 부근). 실패 종류는 나누지 않는다. 그때 셸 출력은 hook 입력의 `tool_response`(실패 이벤트는 `error`)에 있다(`note_output_size`, `discipline.py:930`).
- 세션 시작 안내는 `session_context.main`이 `ledger_section`, `usage_notes` 같은 함수의 줄을 모아 만든다(`hooks/session_context.py:532`). 각 함수는 실패하면 줄 없이 끝난다.
- 저장소별 기록 파일의 자리와 이름은 `ledger.home()`, `ledger.repo_file(root)`의 방식이 있다(`hooks/ledger.py:211`): 격리된 `CLAUDE_DISCIPLINE_HOME`이면 그 아래에 둔다.

## 설계
새 모듈 `hooks/recurrence.py`:
- 기록 한 줄: `{"at", "source": "gate"|"ci", "kind", "session"}`. `session`은 세션 id의 SHA-256 앞 12자다. 경로, 명령, 출력은 없다.
- 순수 함수
  - `valid(row) -> bool`: 자료형과 값(종류는 분류기의 여섯 가지, source는 두 가지)이 맞는 줄만.
  - `recurring(rows, now) -> list[Recurrence]`: 기간(`WINDOW_S` = 14일) 안의 줄을 종류별로 묶어, **함정 종류**(`TRAP_KINDS` = encoding, environment, timeout)이고, 서로 다른 세션 수가 `MIN_SESSIONS`(2) 이상이고, 가장 최근 것이 `FRESH_S`(3일) 안인 것. `Recurrence(kind, sessions, gate, ci)`.
  - `lines(found) -> list[str]`: 종류마다 한 줄. "Gotchas 후보: 이 저장소에서 '인코딩' 실패가 최근 14일에 세션 3개에서 났습니다(게이트 2, CI 1). 원인이 같으면 프로젝트 CLAUDE.md의 Gotchas에 한 줄을 제안하세요. (자동으로 쓰지 않습니다.)"
  - 테스트 실패·린트·기타는 세기만 하고 알리지 않는다: 개발 중에 늘 나는 실패라 함정의 신호가 아니다(초기 판단, 관측 뒤 다시 정한다).
- I/O: `home()`(`~/.claude/state/failures/`, 격리 시 그 아래 `failures/`), `repo_file(root)`, `record(root, source, kind, session_id, now)`(추가 전용), `read(root)`(파일 끝 64KB까지, 깨진 줄은 건너뜀).

`hooks/discipline.py`:
- `note_failure(state, root, source, kind, session_id)`: `CLAUDE_RECURRENCE=0`이면 아무것도 하지 않는다. 세션 안에서 같은 (저장소, source, kind)는 한 번만 적는다(`state["failures_noted"]`). 저장소는 `root`를 품은 가장 안쪽 git 저장소(`_repo_place`), 없으면 `root`. 관측 경계라 모든 예외를 잡아 기록한다.
- 게이트: `record_evidence`에서 게이트가 `failed`로 기록될 때 출력 끝부분(20,000자)을 `classify_failure("", "failure", tail)`에 넣어 종류를 얻고 `note_failure`를 부른다. 출력은 분류에만 쓰고 저장하지 않는다.
- CI: `on_stop`에서 `state["ci"]`의 `status == "failed"`이고 `kind`가 있는 저장소마다 `note_failure`.

`hooks/session_context.py`:
- `recurrence_notes(data, root)`: 실제 세션 시작(compaction 뒤 제외)에서 `recurrence.read` → `recurring` → `lines`. `CLAUDE_RECURRENCE=0`이면 줄 없음. 실패하면 줄 없이 끝난다. `usage_notes` 다음에 붙인다.

`hooks/retention.md`: "쌓이는 것" 표에 실패 종류 기록 한 줄(지우지 않음, 세션당 많아야 몇 줄).
