## Context
settings.json의 허용 목록에 `Edit(//c/dev/**)`가 있어, 원본 데이터 폴더와 백업 폴더도 Claude의 편집 도구(Edit, Write, MultiEdit, NotebookEdit)로 바로 쓸 수 있다. 두 폴더는 git 밖이라 변경 감지도 되지 않는다(마스터 결함 C2). hook 쪽은 P0-05에서 "git 밖 경로는 데이터 블록이 있어야 승인 범위에 든다"로 좁혔지만, 승인이 없을 때의 5파일 허용과 강제 전환 전의 관측 모드에서는 여전히 쓸 수 있다.

목표: 두 폴더를 권한 설정의 deny 목록에 넣어, hook 판정과 무관하게 편집 도구가 쓰지 못하게 한다.

## 확인한 사실
- `settings.json`의 `permissions.deny`에는 같은 형식의 항목이 이미 있다(`Read(//c/Migration_Secrets/**)`, `Edit(~/.claude/discipline/**)`). 허용 쪽 항목은 `Edit(//c/dev/**)`다.
- 두 폴더의 내용은 이 작업에서 읽지 않는다. 폴더가 실제로 있는지도 확인하지 않는다(경로 문자열만 설정에 적는다).
- Quant 프로젝트의 수집기와 백업 작업은 Claude의 편집 도구가 아니라 자체 프로그램으로 이 폴더에 쓴다(마스터 계획의 서술 기준, 미확인). 편집 도구 deny는 그 프로그램에 영향을 주지 않는다. 읽기는 막지 않는다(Quant 작업이 데이터를 읽어야 한다).

## 설계
1. `permissions.deny`에 두 줄을 더한다: `Edit(//c/dev/qr-data/**)`, `Edit(//c/dev/qr-backup/**)`. 다른 설정은 바꾸지 않는다.
2. 테스트로 고정한다: deny 목록에 두 항목이 있고, 기존 deny 항목이 모두 남아 있다(`tests/test_scope.py`에 사례 추가).

### 하지 않기로 한 것: 백업 폴더의 쓰기 거부 ACL
마스터 계획은 `qr-backup`에 쓰기 거부 ACL을 거는 것도 적어 두었다. 이 작업에서는 하지 않는다.
- 백업 작업이 같은 Windows 계정으로 돌고 있다면, 그 계정에 쓰기 거부를 걸면 백업이 멈춘다. 사용자가 정한 "실행 중인 수집기·스케줄러·백업을 변경하거나 중단하지 않는다"와 충돌한다.
- 어느 계정이 백업을 쓰는지 확인하려면 그 폴더와 작업을 조사해야 하는데, 그 폴더는 읽기 금지 대상이다.
- ACL이 의미를 가지려면 백업 전용 계정이 따로 있어야 한다(마스터 계획도 "수집기 전용 계정은 Quant 쪽에 제안만"이라고 적었다). 이것은 Quant 쪽 결정 사항으로 제안만 남긴다.

### 남는 구멍 (보고 대상)
- 셸 명령으로 쓰는 것은 이 deny로 막히지 않는다. P0-07의 사전 판정(관측 모드)과 Stop 검사는 git 밖 경로를 완전히 덮지 못한다.
- Claude가 실행한 프로그램(스크립트)이 쓰는 것도 막히지 않는다.
