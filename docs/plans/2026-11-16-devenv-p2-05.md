## Context
자동 메모리는 작업 폴더별로 나뉘어 있다(`~/.claude/projects/<폴더 이름>/memory/`). 다른 폴더에서 시작한 세션은 관련 메모리를 보지 못하고(CLAUDE.md §2b), 찾으려면 폴더를 하나씩 열어야 한다. 이 항목은 메모리 파일을 낱말로 찾는 읽기 전용 명령 하나를 만든다. 색인이나 DB를 만들지 않고, 메모리를 옮기거나 고치지 않는다(P0-11 메모리 분리는 별도 승인 항목으로 남는다). hook에 연결하지 않으므로 지연에 영향이 없다.

## 확인한 사실
- 메모리 폴더 이름은 작업 폴더 경로에서 영문자·숫자가 아닌 글자를 `-`로 바꾼 것이다. 확인한 예: `C:\` → `C--`, `C:\Users\user\.claude` → `C--Users-user--claude`, `C:\dev\_eval-dryrun\runs\t0-A-1` → `C--dev--eval-dryrun-runs-t0-A-1`(`~/.claude/projects`의 폴더 이름). 공식 문서의 규칙은 미확인이라, 폴더가 없으면 "없음"이라고 말하고 끝낸다.
- 메모리 파일: frontmatter(`name`, `description`, `metadata:` 아래 `type` 등)와 본문. `MEMORY.md`는 색인이라 한 줄 요약이 겹친다.
- 비밀 형태 문자열을 가리는 함수가 있다: `redact.redact(text)`(`hooks/redact.py`).

## 대안 비교
| 선택지 | 내용 | 판단 |
|---|---|---|
| A. 낱말 찾기 명령(추천) | 파일을 그때 읽어 낱말이 모두 들어 있는 메모리를 점수순으로 보여 준다 | 메모리는 수십 개 수준이라 충분하다. 상태가 없어 낡을 것이 없다 |
| B. 색인 파일 | 세션 종료 때 색인을 만들어 두고 찾는다 | 지금 규모에서 얻는 것이 없고, 색인이 메모리와 어긋날 수 있다 |
| C. 임베딩·DB | 뜻으로 찾는다 | 마스터 계획이 "별도 메모리 DB"를 하지 않기로 했다 |

## 설계
`hooks/memory_search.py`(다른 hook 모듈과 같은 폴더에 두되 hook으로 등록하지 않는다. `docs/`는 계획만 추적하고 별도 도구 폴더가 없다):

    python -I hooks/memory_search.py <낱말> [<낱말> ...] [--dir DIR ...] [--all] [--limit N]

- 찾는 곳: `--dir`로 준 폴더들. 없으면 현재 작업 폴더의 메모리 폴더. `--all`이면 `~/.claude/projects/*/memory` 전부.
- 순수 함수
  - `slug(cwd) -> str`: 폴더 이름 규칙.
  - `parse(text) -> Memory(name, description, kind, body)`: frontmatter가 없거나 깨졌으면 이름·설명 없이 본문만.
  - `match(memory, words) -> Hit | None`: 모든 낱말이 이름·설명·본문 중 어딘가에 있어야 한다(대소문자 무시). 점수는 낱말마다 이름 3, 설명 2, 본문 1(가장 높은 것 하나). 일치한 본문 줄은 3개까지, 줄마다 160자까지.
  - `rank(hits, limit)`: 점수 내림차순, 같으면 파일 이름순.
- I/O: `MEMORY.md`는 건너뛴다. 256KB를 넘는 파일과 UTF-8이 아닌 파일은 건너뛰고 수를 센다. 폴더당 파일 2,000개까지.
- 출력(사람과 에이전트가 읽는 글): 일치마다 `파일 경로`, `[종류] 이름 — 설명`, 일치한 줄들. 끝에 "N개 일치(파일 M개를 봄, K개 건너뜀)". 설명과 줄은 `redact.redact`를 거친다.
- 종료 코드: 0 일치 있음, 1 일치 없음, 2 잘못된 입력(낱말 없음, 없는 폴더).
- 쓰기는 하지 않는다. 네트워크도 없다.

`CLAUDE.md` §2b에 사용법 한 줄을 더하는 것은 이 계획에서 하지 않는다(전역 규칙 변경은 제안으로 남긴다).

`--all`과 기본 폴더는 홈 폴더를 바꿔 준 환경(`USERPROFILE`/`HOME`을 임시 폴더로)에서 확인한다. 실제 메모리 폴더는 테스트가 읽지 않는다.

## 위험
- 폴더 이름 규칙은 관찰한 것이다. Claude Code가 규칙을 바꾸면 기본 폴더를 못 찾는다(그때는 `--dir`로 준다).
- `--all`은 모든 프로젝트의 메모리를 읽어 보여 준다. 다른 프로젝트의 메모리가 현재 대화에 들어오는 것이므로, 필요할 때만 쓴다. 이 계획의 실제 사용 확인은 현재 작업 폴더의 메모리로만 한다.
- 낱말 찾기라 뜻이 같은 다른 말은 못 찾는다.
