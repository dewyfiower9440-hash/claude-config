## Context
CI가 실패하면 hook은 "run N failure"까지만 알려 준다. 무엇이 실패했는지는 로그를 직접 받아 읽어야 안다. 이 저장소에서 CI만 실패한 경우는 종류가 반복됐다(콘솔 인코딩, import 정렬, 경로 철자). 실패한 단계 이름과 로그 끝부분에서 종류를 가려 실패 안내에 붙이면, 첫 진단에 드는 왕복이 줄고 P3의 실패 통계에도 쓸 수 있다.

## 확인한 사실
- CI 결과는 `hooks/ci_status.py`의 `fetch_ci(push)`가 GitHub API(`gh api`, 호출당 15초 제한)로 읽고 순수 함수 `ci_verdict`가 판정한다. 결과의 `why` 문자열이 Stop의 실패 안내(`REASON_CI_FAILED`의 `{detail}`)에 그대로 들어간다(`hooks/discipline.py`의 `_content_decision`, `_ci_decision`).
- `fetch_ci`는 `gh run watch|view|list` 명령의 PostToolUse에서만 호출된다(`discipline.py:2117-2120`).
- job 목록(`repos/{repo}/actions/runs/{id}/jobs`)에는 job과 step별 `name`, `conclusion`이 있다. job 로그는 `repos/{repo}/actions/jobs/{job_id}/logs`로 받는다(텍스트).
- 이 저장소에서 실제로 났던 CI 전용 실패(CLAUDE.md `## Gotchas`와 진행 기록): `UnicodeEncodeError: 'charmap' codec can't encode`(cp1252 콘솔), `I001 Import block is un-sorted`(ruff), 경로 철자 차이로 인한 테스트 불일치(`FAIL H-T…`).

## 설계
### 1. 순수 함수 `classify_failure(step, conclusion, log_tail) -> str` (`hooks/ci_status.py`)
종류와 판별 순서(앞의 것이 우선):
1. `timeout`: 결론이 `timed_out`이거나 로그에 실행 시간 초과 문구.
2. `encoding`: `UnicodeEncodeError`, `UnicodeDecodeError`, `codec can't encode/decode`.
3. `environment`(로그 기준): `ModuleNotFoundError`, `No module named`, `is not on PATH`, `command not found`, `is not recognized as`.
4. `lint`: `FAIL ruff`, `Would reformat`, ruff 규칙 코드 줄(`I001 [*]` 형식), `Found N error`.
5. `test`: `FAIL `로 시작하는 줄, `FAILURES: 1` 이상, `AssertionError`, `N failed`.
6. `environment`(단계 이름 기준): 실패한 단계가 설치·체크아웃·setup 단계.
7. `other`: 위에 해당 없음, 또는 로그를 읽지 못함.

### 2. 어댑터 (`fetch_ci` 안)
- 판정이 `failed`일 때만: 실패한 run의 job 목록에서 실패한 job과 그 실패 step 이름을 찾고, 그 job의 로그를 받아 끝부분 20,000자만 분류에 쓴다. 호출마다 시간 제한(목록 15초, 로그 10초)이 있다.
- 결과에 `kind`를 넣고, `why` 끝에 `원인 분류: <한국어 이름> (실패 단계: <step 이름 80자까지>)`를 붙인다. Stop의 안내는 `why`를 그대로 쓰므로 `discipline.py`는 고치지 않는다.
- 목록이나 로그를 못 받으면 단계 이름만으로 분류하거나 `other`로 둔다. 분류 실패가 CI 판정(`status`)을 바꾸지 않는다.
- 로그 본문은 저장하지 않고 로그에도 쓰지 않는다(분류에만 쓰고 버린다).

### 검토한 대안
| 방식 | 판단 |
|---|---|
| A. 단계 이름 + 로그 끝부분의 고정 패턴 | **채택**: 이 저장소의 실제 실패 세 종류를 가른다 |
| B. 로그 전체를 모델에게 넘겨 분류 | 기각: hook에서 모델을 부르지 않는다. 로그가 컨텍스트로 들어온다 |
| C. 단계 이름만 | 기각: 이 저장소는 게이트 한 단계에서 모든 실패가 난다 |

## 위험
- 패턴은 이 저장소의 실패에 맞춰져 있다. 다른 프로젝트(pytest, vitest)에서는 `test`/`other`로 뭉칠 수 있다. 분류는 힌트이고, 틀려도 CI 판정에는 영향이 없다.
