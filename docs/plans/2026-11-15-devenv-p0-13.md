# devenv P0-13: 오래된 세션 상태 파일 정리

- 마스터 계획: `docs/plans/2026-11-11-devenv-evolution-master.md` 14번 항목
- 선행: P0-12 완료(CI run 43656415509)
- 저장 위치: `docs/plans/2026-11-15-devenv-p0-13.md`
- 승인 근거: 사용자 지시 2026-11-14 "앞으론 승인안받아도된다 ... 개발환경 고도화 작업 마무리해라"

## Context
discipline hook은 세션마다 상태 파일(`<세션>.json`)과 잠금 파일(`<세션>.lock`)을 임시 폴더의 `claude-discipline`에 만든다. 지우는 코드가 없어 계속 쌓인다. 마스터 계획을 쓸 때 2,973개였고, 지금은 34,480개(64MB)다(2026-11-15 측정, 이름과 수정 시각만 집계). 대부분은 테스트가 만든 세션이다: 모두 7일 이내이고 하루 안에 생긴 것이 19,291개다.

목표: 일정 기간 쓰이지 않은 세션의 상태 파일과 잠금 파일을 지운다. 살아 있는 세션의 파일과 복구용 사본(`.corrupt-*`, `.recovered-*`)은 건드리지 않는다.

## 확인한 사실
- 폴더 내용(이름 패턴 집계): `<id>.json` 20,793개, `<id>.lock` 13,419개, `<id>.json.recovered-*` 10개 안팎, `<id>.json.corrupt-*` 몇 개. 하위 폴더는 없다.
- 상태 파일은 hook이 실행될 때마다 다시 쓰인다(`session_store.save`). 따라서 수정 시각이 오래됐다는 것은 그 세션에서 hook이 그동안 한 번도 돌지 않았다는 뜻이다.
- 잠금 파일은 hook 실행 중에만 열려 있다(`session_store.locked`). Windows에서는 열려 있는 파일을 지울 수 없으므로, 실행 중인 세션의 잠금은 지우려 해도 실패한다.
- 대화 기록(트랜스크립트)은 `cleanupPeriodDays`(기본 30일)가 지난 뒤 지워진다(`tests/_baseline/2026-11-11-p0-02.md` 7번). 그보다 오래된 세션은 다시 열 수 없다.
- SessionEnd hook(`hooks/handoff.py end`, P0-12)이 세션이 끝날 때마다 실행되고 제한 시간은 5초다. 정상 실행은 0.6초였다.

## 설계
### 1. 정리 모듈 (새 파일 `hooks/state_gc.py`)
- 순수 함수 `stale_entries(entries, now, ttl_s) -> list[str]`: `(이름, 수정 시각)` 목록에서 지울 이름을 고른다.
  - 대상 이름은 `<영숫자·밑줄·하이픈>.json`과 `<같은 형식>.lock`뿐이다. 그 밖의 이름(복구용 사본 포함)은 대상이 아니다.
  - `.json`은 수정 시각이 TTL보다 오래됐을 때만 지운다. `.lock`은 짝이 되는 `.json`이 지워질 때 함께 지우고, 짝이 없는 `.lock`은 자신이 TTL보다 오래됐을 때 지운다. 짝이 되는 `.json`이 남아 있으면 `.lock`도 남긴다.
- `sweep(folder, now, ttl_s, limit, budget_s) -> (지운 수, 실패 수)`: 폴더를 한 번 훑어(`os.scandir`, 하위 폴더와 링크는 건너뜀) 위 함수로 고른 파일을 지운다. 한 번에 최대 2,000개, 1초까지만 쓴다. 지우지 못한 파일(사용 중, 권한)은 세고 넘어간다.
- TTL 기본값은 14일이다. 환경 변수 `CLAUDE_STATE_TTL_DAYS`로 바꿀 수 있고, 1일 미만이나 잘못된 값은 기본값으로 본다.

### 2. 실행 시점
- `handoff.py end`가 기록을 쓴 뒤 `state_gc.sweep`을 한 번 부른다. 남은 시간이 1초보다 적으면 건너뛴다. 정리의 실패는 종료 코드에 영향을 주지 않는다(stderr 한 줄).
- 저장소 밖에서 끝난 세션에서도 정리는 실행한다.

### 3. 영향
- 14일 넘게 쓰지 않은 세션을 다시 열면 hook이 그 세션을 새 세션처럼 다룬다(기준선과 "미검증 변경" 기록이 없어진다). 그 세션에서 14일 전에 남긴 미검증 변경은 더 이상 Stop에서 지적되지 않는다.
- 지금 쌓여 있는 34,480개는 모두 7일 이내라 당장은 지워지지 않는다. 14일이 지나면서 세션 종료 때마다 최대 2,000개씩 줄어든다.

### 검토한 대안
| 방식 | 판단 |
|---|---|
| A. 수정 시각 기준 TTL, 세션 종료 때 조금씩 | **채택** |
| B. 지금 한 번에 전부 삭제 | 기각: 살아 있는 세션(이 세션 포함)의 상태가 사라진다 |
| C. 테스트가 만든 파일만 골라 삭제 | 기각: 테스트 세션과 실제 세션을 이름으로 구분할 수 없다 |

별도 제안(이 작업에서 하지 않음): 게이트(`run_all.py`)가 테스트를 전용 임시 폴더에서 돌리고 끝나면 통째로 지우면, 테스트가 만드는 파일이 애초에 쌓이지 않는다. 테스트 전반의 경로 가정을 확인해야 해서 따로 다룬다.
