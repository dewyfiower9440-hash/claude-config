## Context
새 세션이나 요약(compaction) 뒤의 세션은 "이 작업이 어디까지 검증됐는가"를 계획 체크박스와 사람이 쓴 요약으로만 안다. P1-01이 남기는 작업 원장에는 hook이 판정한 상태(구현만 됨, 로컬 검증, CI 검증)가 있다. 세션 시작 때 진행 중인 계획마다 원장의 마지막 상태를 보여 주고, 지금의 git 상태와 어긋나 보이는 점을 함께 알려 준다. 보여 주기만 하며 승인이나 검증을 되살리지 않는다.

## 확인한 사실
- 세션 시작 문맥은 `hooks/session_context.py`가 만든다. 저장소 안에서는 `read_git`(브랜치, 변경 파일, 최근 커밋), `read_plans`(주 계획과 진행 중·막힌 계획 요약 `PlanSummary`: 경로, 상태, task, 미체크 수), 그리고 안내 줄(`session_notes`, `plan_notes`)을 `build_context`가 한도 안에서 합친다(안내 한 줄 240자, 안내 전체 1,200자).
- 원장 읽기는 `hooks/ledger.py`의 `read(root) -> (entries, 문제 | None)`와 `latest(entries) -> {task: entry}`다. 저장소 경로의 철자는 `repo_file`이 정규화한다. 줄에는 `task, state, at, review, content`가 있다.
- 원장의 `content` 값(내용 해시들의 해시)을 지금 내용과 직접 비교하려면 저장소 전체의 내용 해시를 다시 계산해야 한다(git 조회 여러 번). 세션 시작에는 과하다.

## 설계
### 1. 순수 함수 `ledger_notes(summaries, latest, problem, dirty, head_at) -> list[str]` (`hooks/session_context.py`)
- 진행 중인 계획(task가 있는 것, 4개까지)마다 한 줄:
  - 원장에 그 task의 줄이 있으면: 상태 이름(구현됨·미검증 / 로컬 검증됨 / CI 검증됨 / 실패 상태 / 결과 불명), 기록 시각, 리뷰 판정.
  - 어긋남 표시: 검증된 상태인데 지금 작업 폴더에 변경이 있으면 "그 뒤 변경이 있을 수 있음", 기록 시각보다 뒤에 커밋이 있으면 "기록 뒤에 커밋이 있음".
  - 줄이 없으면 "원장 기록 없음".
- 원장에 문제(서명·연결 불일치, 읽을 수 없는 줄)가 있으면 그 사실을 한 줄로 먼저 적는다.
- 진행 중인 계획이 없으면 아무 줄도 내지 않는다.
- 첫 줄(제목)에 "참고용이며 승인·검증을 복원하지 않는다"를 적는다.

### 2. 연결 (`session_context.main`)
- 저장소 안에서 `ledger_section(root, summaries, info)`가 원장을 읽고, 마지막 커밋 시각을 git으로 한 번 조회해(`git log -1 --format=%ct`) 위 함수를 부른다. 결과 줄은 종료 기록(`session_notes`)과 계획 목록(`plan_notes`) 사이에 넣는다.
- 실패(파일, 형식, git)는 줄 없음으로 처리한다. 세션 시작을 실패시키지 않는다.
- 원장은 여기서도 읽기만 한다. 어떤 판정에도 쓰이지 않는다(문맥에 보일 뿐).

### 검토한 대안
| 방식 | 판단 |
|---|---|
| A. 원장의 마지막 상태 + 시각·작업 폴더 상태로 어긋남 힌트 | **채택**: git 조회 한 번 |
| B. 내용 해시를 다시 계산해 원장의 `content`와 정확히 비교 | 기각: 세션 시작마다 저장소 전체 해시 계산 |
| C. 원장 상태가 검증됨이면 Stop의 검증 요구를 생략 | 기각: 기록은 증거가 아니다(원장은 판정에 쓰지 않는다는 P1-01의 원칙) |
