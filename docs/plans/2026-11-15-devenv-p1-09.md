## Context
종료 기록(handoff)과 작업 원장은 사람이 쓴 글자를 그대로 담는 칸이 있다: 계획의 "다음 단계" 문구, 계획 파일 경로, 브랜치 이름, 작업 id. 계획 단계에 누군가 토큰을 붙여 넣었다면("`ghp_…`로 인증해 push") 그 문자열이 `~/.claude/state/` 아래 파일에 남고, 다음 세션의 문맥으로도 들어간다. 사용자의 원칙은 "비밀정보와 인증 토큰은 로그에 남기지 않는다"이다. 이 기록들에 글자를 쓰기 전에 토큰 형태의 문자열을 가린다.

## 확인한 사실
- 종료 기록의 글자 칸은 `hooks/handoff.py`의 `clean()`을 반드시 거친다(쓸 때와 읽을 때 모두, `one_line`으로 한 줄로 만든 뒤 길이 제한). 대상 칸: `session_id`, `reason`, `git_root`, `branch`, `head`, `plan`, `next_step`.
- 원장의 글자 칸은 `hooks/ledger.py`의 `clean()`을 거친다(`task`, `approval`, `state`, `content`, `session`, `review`). 이 가운데 사람이 쓴 글자는 `task`(계획 frontmatter의 값)뿐이다.
- 세션 시작 문맥에는 종료 기록의 `next_step`·`plan`·`branch`와 원장의 `task`가 들어간다(`handoff.restore_lines`, `session_context.ledger_notes`). 둘 다 위의 `clean()`을 거친 값을 쓴다.
- 관측 기록 네 가지와 사용량 기록에는 글자 칸이 없다(숫자와 고정된 이름뿐). 값을 가리는 함수는 저장소에 아직 없다(`hooks/guard.py`의 패턴은 비밀 **파일 경로**용이다).

## 설계
### 1. 순수 모듈 `hooks/redact.py`
- `redact(text) -> str`: 아래 형태를 `[가림]`으로 바꾼다. 문자열이 아니면 그대로 돌려준다.
  - GitHub 토큰(`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`), `sk-`로 시작하는 API 키(OpenAI·Anthropic 형식), AWS 액세스 키 id(`AKIA…`/`ASIA…`), Slack 토큰(`xox?-…`), JWT(점 두 개로 이어진 `eyJ…`), PEM 개인키 머리말.
  - `이름=값`, `이름: 값` 형태에서 이름이 `password`, `passwd`, `pwd`, `secret`, `token`, `api_key`, `apikey`, `access_key`, `authorization` 계열이면 **값만** 가린다(이름은 남긴다).
  - `Bearer <값>`, URL 안의 `사용자:비밀번호@`에서 비밀번호.
- 가리지 않는 것(오탐 방지): 커밋 해시(40자 이하 16진수), UUID 형태의 세션 id, 파일 경로, 한글 문장, 8자 미만의 짧은 값.
- 가린 결과에 다시 적용해도 변하지 않는다.

### 2. 적용
- `handoff.clean()`: 글자 값에 `one_line` 다음, 길이 제한 **전에** `redact`를 적용한다(잘린 토큰 조각이 패턴을 피해 남지 않게).
- `ledger.clean()`: 같은 방식으로 글자 값에 적용한다. 원장 줄의 HMAC은 가린 뒤의 값으로 계산되므로 검증에는 영향이 없다.
- 읽을 때도 `clean()`을 거치므로, 이 작업 전에 쓰인 종료 기록의 값도 문맥으로 나갈 때는 가려진다. 원장의 옛 줄은 `clean`을 다시 거치지 않고 읽히지만, 문맥으로 나가는 `task`는 `ledger_notes`가 자르고 정리한다 → 거기에도 `redact`를 적용한다(`session_context.py`).

| 방식 | 판단 |

| B. 엔트로피가 높은 긴 문자열을 모두 가림 | 기각: 커밋 해시·내용 해시·세션 id가 가려져 기록이 쓸모없어진다 |

## 위험
