# devenv P1 단계 계획: 개발 신뢰성

- 마스터 계획: `docs/plans/2026-11-11-devenv-evolution-master.md` 16번 항목(17~24번의 범위 정의)
- 선행: P0 마감(P0-14 CI run 43668429513, P0-15 CI run 43674079732). 남은 P0 항목: P0-11(메모리 분리, 사용자 판단 대기), 관측 모드의 강제 전환(2026-11-22 이후).
- 승인 근거: 사용자 지시 2026-11-14 "앞으론 승인안받아도된다 ... 개발환경 고도화 작업 마무리해라"
- 이 문서는 범위 정의다. 각 항목은 자기 계획 문서(`docs/plans/YYYY-MM-DD-devenv-p1-NN.md`)를 따로 쓰고 그 계획의 승인 범위 안에서 구현한다.

## 공통 규칙
- 순서대로 하나씩 한다. 항목마다: 계획 → 테스트 먼저 → 구현 → 게이트 → code-reviewer 1회 → 반영 → 게이트 → 커밋 → push → CI 확인 → 마감 기록.
- 새로 넣는 판정은 처음에는 **관측만** 한다(기록하고 알리되 막지 않는다). 막는 쪽으로의 전환은 관측 결과를 본 뒤 별도 작업으로 한다.
- hook에 넣는 작업은 지연을 잰다. P0-15 뒤의 값(`tests/_baseline/2026-11-11-post-p0-15.json`)보다 hook당 p50이 30ms 넘게 늘면 원인을 적고 줄인다(초기 값).
- 기록은 상태만 담는다. 승인을 주거나 되살리는 데 쓰이지 않는다.
- 하지 않는 일: Quant 저장소 변경, 운영 설정의 강제 전환, 새 subagent·skill·MCP 서버 추가.

## 항목

### P1-01 작업 원장 (마스터 17번)
- 문제: 어떤 작업이 어느 검증 상태까지 갔는지는 세션 상태에만 있고 세션이 끝나면 사라진다. 다음 세션은 계획 체크박스와 대화 요약에 의존한다.
- 할 일: 저장소별 추가 전용 기록(`~/.claude/state/ledger/`)에 승인된 작업의 상태 변화(Implemented, Locally Verified, CI Verified, Blocked/Unknown — CLAUDE.md §1.6의 이름)를 남긴다. Stop hook이 이미 계산하는 증거에서 상태를 뽑는다. 각 줄은 앞 줄의 해시와 HMAC을 담아 중간 수정·삭제를 알아챌 수 있게 한다.
- 완료 기준: 상태 변화가 생길 때만 한 줄이 추가된다. 변조·잘림이 검출된다. 원장은 어떤 판정에도 입력으로 쓰이지 않는다.

### P1-01b 턴 중 작업 전환 때의 범위 판정
- 문제(P0 진행 중 반복 관찰): 한 턴 안에서 승인 작업이 바뀌면 Stop이 앞 작업의 정상 변경을 새 작업의 "범위 밖"으로 보고한다.
- 할 일: 새 승인이 기록되는 시점에, 그때까지의 변경이 직전 승인의 범위 안이었는지 판정해 두고, 안이었으면 Stop의 범위 판정에서 그 변경을 다시 세지 않는다. 직전 승인이 없거나 범위를 벗어난 변경은 지금처럼 보고한다.
- 완료 기준: 정상 전환에서 거짓 보고가 없다. 승인 없이 한 변경이나 범위 밖 변경을 전환으로 가릴 수 없다(공격 사례 테스트).

### P1-02 내용에 묶인 리뷰 (마스터 18번)
- 문제: 리뷰 여부는 시각(`last_review`)으로만 판정한다. 리뷰 뒤에 코드가 바뀌어도 리뷰한 것으로 남는다.
- 할 일: code-reviewer가 끝난 시점의 내용 해시를 기록하고, 그 뒤 내용이 바뀌면 리뷰를 무효로 본다. 리뷰 게이트(`CLAUDE_REVIEW_GATE`)의 기본값은 그대로 끄고, 켰다면 막았을 경우를 관측 기록으로 남긴다.
- 완료 기준: 리뷰 후 변경이 "리뷰 안 됨"으로 판정된다. 관측 기록이 쌓인다. 기본 동작은 변하지 않는다.

### P1-03 테스트 누락 탐지 (마스터 19번)
- 할 일: 한 작업에서 코드 파일은 바뀌었는데 테스트 파일은 하나도 바뀌지 않았으면 Stop에서 한 번 알린다(막지 않음). 문서·설정만 바뀐 경우는 제외한다.
- 완료 기준: 정상 사례(테스트 동반)에서 알림 없음, 누락 사례에서 알림 1회, 관측 기록.

### P1-04 출력 크기 계측과 위임 권고 (마스터 20번)
- 할 일: 셸 도구 출력 크기를 기록하고, 테스트 실행류 명령의 출력이 기준(초기 8KB)을 넘으면 test-runner에 맡기라는 안내를 한 번 넣는다.
- 완료 기준: 크기 기록, 기준 초과 때 안내 1회, 기준 아래에서는 침묵.

### P1-05 CI 실패 원인 분류 (마스터 21번)
- 할 일: CI가 실패했을 때 실패한 job·step 이름과 로그 끝부분에서 종류(린트·형식, 테스트 실패, 인코딩, 환경·설치, 시간 초과, 기타)를 가려 Stop의 실패 안내에 붙인다. 분류하지 못하면 "기타"로 둔다.
- 완료 기준: 이 저장소에서 실제로 났던 실패 로그(인코딩, import 정렬, 경로 철자)를 고정 입력으로 한 테스트가 통과한다. 네트워크 호출에는 시간 제한이 있다.

### P1-06 재시작 복구 (마스터 22번)
- 할 일: 세션 시작 때 원장의 마지막 상태를 현재 git 상태·계획 파일과 대조해 보여 준다(예: 원장은 Locally Verified인데 그 뒤 커밋이 달라짐, 계획은 진행 중인데 원장 기록이 없음).
- 완료 기준: 일치·불일치 사례별 표시, 안내 길이 한도 준수, 승인 복원 없음.

### P1-07 보존 정책과 디스크 경고 (마스터 23번)
- 할 일: `~/.claude/projects`와 `file-history`의 크기를 재고(세션 종료 때, 시간 한도 안에서) 기준을 넘으면 다음 세션 시작 때 알린다. 삭제는 하지 않는다. 보존 기간 설정(`cleanupPeriodDays`)의 현재 값과 권고를 문서에 적는다.
- 완료 기준: 측정값 기록, 기준 초과 때 알림, 삭제 없음.

### P1-09 기록의 비밀정보 가림 (마스터 24번)
- 할 일: handoff와 원장에 쓰는 글자 값(계획의 다음 단계 문구, 브랜치 이름 등)을 쓰기 전에 가림 함수에 통과시킨다(토큰·비밀번호 형태의 문자열을 치환).
- 완료 기준: 알려진 토큰 형태가 기록에 남지 않는다. 일반 문구는 그대로다.
