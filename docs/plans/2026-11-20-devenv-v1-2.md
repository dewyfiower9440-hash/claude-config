## 가정
- 리뷰 우회는 기록이 남는 명시적 탈출구로만 허용한다.
  - 커밋 메시지에 트레일러 `Review-Skipped: <이유>`가 있으면 통과시키고, 알림으로 기록한다.
  - 트레일러가 없으면, 내용이 같아도 재시도할 때마다 막는다.
  - 메시지는 `-m`, `-F -`의 heredoc 본문, `-F <파일>`(그 파일을 읽음)에서 찾는다. 읽을 수 없으면 트레일러가 없는 것으로 본다.
  - `CLAUDE_COMMIT_REVIEW=notify|off`는 그대로 남긴다.
- 인라인 패치 검사는 `python`(`py`, `python3`, `uv run python` 포함)의 `-c` 코드나 heredoc 본문, 그리고 `cat`·`tee`로 파일을 쓰는 heredoc을 본다.
  - 파일을 쓰는 코드(`write_text`, `write_bytes`, `open(..., 'w'/'a'/'wb')`, `.write(`)이거나 리다이렉트 대상이 있고, 본문에 백슬래시가 있으면 대상이다.
  - 기본은 같은 명령 내용당 한 번 막기(`CLAUDE_INLINE_PATCH=block`)다. `notify`·`off`로 완화할 수 있다.
  - 막는 메시지는 Edit/Write 도구를 쓰거나, 스크립트를 Write로 파일에 쓰고 실행한 뒤 repr로 확인하라고 안내한다.
  - 커밋 메시지 heredoc(`git commit -F - <<EOF`)은 대상이 아니다.
- test-runner 알림은 세션당 최대 3회로 줄인다(`MAX_TEST_ADVICE_PER_SESSION=3`, 초기값이며 측정 뒤 다시 조정).
  - 문구에 출력 줄이는 방법(`-q`, 파일로 리다이렉트한 뒤 `tail`)을 먼저 둔다.
  - Explore 알림은 이번에 바꾸지 않는다(수용 측정 표본 2건으로 부족).
- 승인과 구현은 `C:\dev\_wt\claude-config`에서 시작한 세션이 `/implement docs/plans/2026-11-20-devenv-v1-2.md`로 한다. 이 세션(C:\dev\auto)은 git 밖이라 승인이 작업트리에 묶이지 않는다(v1.1에서 확인).

## 리스크와 대응
- 커밋 차단이 매번 걸려 흐름이 끊긴다. 대응:
  - 탈출구는 트레일러 한 줄이고, 메시지가 그 사용법을 알려 준다.
  - 급하면 `CLAUDE_COMMIT_REVIEW=notify`로 완화한다.
  - 트레일러 사용 수를 감시 보고서로 측정해, 많으면 접근 C(작은 델타 면제)를 결정한다.
- 인라인 패치 검사가 틀리게 잡는다(오탐: 정규식 이스케이프 `\d`가 든 읽기 전용 스크립트를 쓰기로 판정). 대응:
  - 쓰기 신호와 백슬래시가 함께 있을 때만 잡는다.
  - 같은 명령당 한 번만 막는다.
  - 오탐 케이스를 테스트로 고정한다.
  - `notify`·`off`로 완화할 수 있다.
- 인라인 패치 검사가 놓친다(미탐: `sed -i`나 `perl -pi`의 백슬래시). 대응: 정규식 치환은 백슬래시가 정상이라 이번 범위에서 뺀다. 리스크로 기록하고 측정 뒤 결정한다.
- `-F <파일>` 읽기 I/O 오류. 대응: 읽지 못하면 트레일러 없음으로 보고 막는다(fail-closed). 검사 자체의 예외는 막지 않는다(기존 원칙).
- 훅 지연이 늘어난다. 대응: 파싱은 이미 하는 `shellparse` 결과를 다시 쓰고, 추가 I/O는 `-F` 파일 읽기뿐이다. 단계 10의 훅 지연 비교로 확인한다.
- 되돌리기: 단계마다 커밋하므로 `git revert`로 되돌린다. 훅이 잠기면 `git -C ~/.claude checkout v1.1 -- hooks settings.json`(CLAUDE.md Release 절차).
