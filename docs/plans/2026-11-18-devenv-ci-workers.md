# devenv: CI에서는 게이트를 4개 동시 실행으로 돌린다

- 저장 위치: `docs/plans/2026-11-18-devenv-ci-workers.md`
- 승인 근거(사용자 결정 2026-11-18, 그대로 인용): "CI에만 GATE_WORKERS=4를 주는 변경을 한다. 워크플로 변경이라 작은 자기 계획(devenv-ci-workers)으로 승인받는다. 근거(CI wall: 4개 402초, 6개 514초)를 계획에 적는다. 로컬 게이트는 6을 유지한다."
- push: 커밋은 push하고 CI를 끝까지 따라간다(사용자 결정 2026-11-16).
- 목표와의 연결: 검증·신뢰성 "CI 흔들림 0건(시간 예산 테스트 포함)".

## Context
로컬 게이트는 600초 안에 끝나야 해서 동시 실행을 6개로 올렸다(2026-11-17). CI에는 그 한도가 없는데 같은 6개로 돌고, 코어가 적은 러너에서는 경합만 늘어난다. 2026-11-17 밤 한 실행이 평소의 7배 넘게 느려져 시간 예산에 기대는 테스트 5개 모듈이 실패했다(재실행은 성공).

## 근거 (CI 로그의 `gate:` 줄, 2026-11-17~18)
| 동시 실행 | CI wall | 모듈 합계 | 실행 |
|---|---|---|---|
| 4 | 402초 | 1,567초 | run 44000876517 (모듈 37개, 분할 전) |
| 6 | 336, 333, 439, 514초 | 1,983 ~ 2,918초 | run 44008275292, 44040270166, 44064029786, 44074879009 |
| 6 | 595, 641초 | 3,512, 3,790초 | run 44053551115, 44065641670(2차) |
| 6 | 3,292초 (**실패**) | 19,500초 | run 44065641670(1차) |

- 6개일 때 합계가 4개일 때보다 27% 이상 크다(같은 일을 하는 데 경합으로 더 든다). 빠른 실행에서는 6개가 wall을 60~70초 줄이지만, 느린 실행에서는 줄이지 못하고 모듈 하나하나가 느려져 시간 예산 테스트가 위험해진다.
- 4개의 측정은 1건이고 모듈 수가 그 뒤 늘었다(테스트 추가). 그래서 "4개가 더 빠르다"가 아니라 "4개가 모듈별 시간을 줄여 시간 예산 테스트에 여유를 준다"가 이 변경의 근거다. 변경 뒤 CI의 `gate:` 줄로 다시 잰다.
- `tests/run_all.py`는 `GATE_WORKERS` 환경 변수를 읽는다(`workers_from_env`; 양의 정수가 아니면 종료). 기본값(`DEFAULT_WORKERS = 6`)은 건드리지 않는다.

## 바꾸는 것
- `.github/workflows/ci.yml`의 게이트 단계에 환경 변수를 준다:
  ```yaml
      - name: Quality gate (same command as the local gate in CLAUDE.md)
        shell: pwsh
        env:
          GATE_WORKERS: "4"  # the runner has few cores and no 600 s limit; locally the default (6) runs
  ```
  실행하는 명령(`python -I tests/run_all.py`)은 그대로다: CLAUDE.md의 "CI는 로컬 게이트와 같은 명령"이 유지된다.
- `tests/test_run_all.py`에 검사 하나: 워크플로의 게이트 단계가 `GATE_WORKERS`를 주면 그 값이 양의 정수이고 `DEFAULT_WORKERS` 이하다(오타가 CI에서야 드러나는 것을 막고, CI가 로컬보다 많이 돌리게 바뀌는 것을 잡는다). 워크플로 글을 정규식으로 읽는다(YAML 해석기를 더하지 않는다).
- 새 hook, 새 문서는 없다.

## 위험
- 빠른 러너에서는 CI가 60~70초쯤 길어질 수 있다(한도가 없어 해가 없다).
- 4개여도 러너가 7배 느려지면 시간 예산 테스트는 실패할 수 있다. 그때는 사용자 결정 2에 따라 테스트를 느슨하게 하지 않고, 시간 대신 결정적인 기준(git 호출 횟수 등)으로 바꾸는 안을 P5-08에 넣어 제안한다.
- 워크플로 파일의 편집은 guard나 권한 규칙이 확인을 요구할 수 있다. 막히면 우회하지 않고 보고한다.
- 로컬 게이트 여유는 57초(wall 543초)다. 이 변경은 로컬 시간을 바꾸지 않는다(검사 하나, 1초 미만). `test_task_switch` 분할은 여전히 다음 항목이다.
