## 선택한 접근
한 가지만 합리적이다: 가드의 기존 규칙 지점(`as_path`, `glob_reaches_*`, `check_recursive_delete`, `shell_guarded_writes`, `git_writes`, `check_read_only_writes`)을 입력별로 고치고, 새 판정은 "이름 추정" 대신 **실제 전개**(중괄호는 문자열로, 글롭은 파일 시스템으로)로 한다. 가드 바깥의 네 결함은 각자의 모듈에서 한 줄씩 고친다. 대안으로 본 것: (a) 가드를 "허용 목록 셸"로 다시 쓰기 — 범위 밖이고 코퍼스 11,012개의 오차단 위험이 크다. (b) 글롭을 더 정교한 점유율 규칙으로 — `cat .e*`를 잡으려면 `*.py` 같은 정상 패턴도 걸린다; 실제 전개는 cwd에 그 파일이 있을 때만 막으므로 정확하다(시작 폴더를 알 수 없을 때만 기존 규칙으로 돌아간다).
설계 원칙: 판정 함수는 순수하게(`brace_alternatives(word) -> list[str]`, `expand_glob(word, cwd, dialect) -> list[str]`), 파일 시스템 접근은 `expand_glob` 한 곳에 상한(`**` 제외, 결과 200개)을 두고 둔다. 모든 변경은 테스트 먼저(실패를 보고 고친다), 바뀌는 기존 기대값은 진행 기록에 적는다.

- read-only subagent의 git은 허용 목록으로 바꾼다: `log show diff status blame grep ls-files ls-tree rev-parse rev-list cat-file describe shortlog reflog name-rev merge-base check-ignore check-attr var version help count-objects for-each-ref diff-tree diff-index` + `GIT_READ_FORMS`의 읽기 형태. `fetch`는 지금처럼 거부. `-c alias.*`는 거부.

## 리스크와 대응
- 글롭 실제 전개가 큰 폴더에서 느리다 → `**`는 전개하지 않고 결과 200개 상한, 패턴 토큰에만 호출; bench로 확인.
- `cmd /c` 스크립트를 PowerShell 방언으로 파싱하면 다른 cmd 명령의 판정이 바뀔 수 있다 → 코퍼스 재생으로 본다; 새 차단이 나오면 의도된 것만 등록하고 나머지는 되돌린다.
- 허용 목록 git은 리뷰어가 쓰던 읽기 명령을 막을 수 있다 → 목록은 `GIT_READ_FORMS`와 합치고, 격리 시험(code-reviewer 1회, 단계 8)에서 거부된 명령이 읽기면 목록에 더한다.
- `above_protected`를 넓히면 `%LOCALAPPDATA%` 위를 훑는 정상 명령이 막힌다 → 정상 범위(`C:\dev`, 프로젝트 폴더, scratchpad)는 영향 없음을 테스트로 고정; 사용자가 홈 전체를 훑을 일은 `git grep`으로 안내(기존 문구).
- `MIN_KEY_BYTES` 32: 손으로 만든 짧은 키가 있다면 `StoreCorrupt` → 그 경우 `admin_reset` 경로가 안내한다(기존 동작). 운영본 키 파일은 도구로 읽지 않는다.
- 승인 바인딩: 세션이 `C:\dev`에서 시작됐다 → 가정 1의 처리.
- 되돌리기: 모든 변경은 커밋 단위라 `git revert <sha>`; 운영본은 `git -C ~/.claude checkout <직전 커밋> -- hooks settings.json`(CLAUDE.md Release).
