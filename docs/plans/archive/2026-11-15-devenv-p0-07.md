## Context
승인 범위 판정은 Edit·Write 같은 편집 도구에만 적용된다. Bash와 PowerShell로 파일을 쓰면(`>` 리다이렉션, `sed -i`, `Set-Content`, `rm` 등) 실행 전에는 아무 판정도 받지 않고, 끝난 뒤 Stop 검사에서만 드러난다. git 밖의 경로는 Stop에서도 보이지 않는다.

목표: 셸 명령에서 **읽어 낼 수 있는** 쓰기 대상을 실행 전에 뽑아 편집 도구와 같은 규칙으로 판정한다. 모든 쓰기를 알아낼 수는 없다(스크립트 내부, 변수, 프로그램이 스스로 여는 파일). 그 한계를 문서에 적고, 놓친 것은 기존 Stop 검사가 맡는다.

P0-06과 같은 스위치를 쓴다. 기본 모드(warn)에서는 거부하지 않고 관측 기록만 남기므로 지금 동작이 바뀌지 않는다. enforce에서만 거부한다.

## 확인한 사실
- `hooks/shellparse.py`의 `parse(command, dialect)`는 명령을 단순 명령 목록으로 나눈다. 리다이렉션은 낱말로 남는다(예: `['echo', 'hi', '>', 'out.txt']`, `['cat', 'a', '>>', 'b c.txt', '2', '>', 'err.log']`). `program_and_args`가 프로그램 이름을 정규화한다. 파싱할 수 없으면 `ParseError`를 낸다.
- `hooks/verification.py`의 `cwd_at(cmds, index, cwd)`가 `cd`를 따라 그 시점의 작업 폴더를 구하고, `_resolve`가 `~`, `$HOME`, Git Bash의 `/c/...` 경로를 Windows 경로로 바꾼다.
- `on_pre`의 셸 분기(`hooks/discipline.py`, "D-5" 주석 아래)는 저장소 스냅샷과 테스트 파일 삭제 확인만 하고 `return`한다.
- P0-06의 `authz_verdict`, `observe_authz`, `REASON_AUTHZ`, `AUTHZ_MODE`와 P0-05의 `in_approved_scope`, `ignored_path`를 그대로 쓸 수 있다.
- settings.json의 `discipline.py pre` matcher(190행)와 `post` matcher(212행)에 NotebookEdit가 없다. P0-06 리뷰에서 나온 남은 항목이다(hook 코드는 이미 `notebook_path`를 읽는다).

## 설계
### 1. 쓰기 대상 추출 (새 모듈 `hooks/shellwrites.py`, 순수 함수)
`write_targets(command, dialect, cwd) -> (paths, unresolved)`
- `paths`: 절대 경로 목록. `unresolved`: 쓰기인 것은 알지만 대상을 정할 수 없는 경우의 수(변수, 명령 치환, 파싱 실패).
- 인식하는 것:
  - 리다이렉션 `>`, `>>`, `>|`, `2>`, `&>`의 대상. `/dev/null`, `$null`, `NUL`, `&1` 같은 것은 제외.
  - Bash: `tee`, `sed -i`, `cp`·`mv`·`install`(목적지, `mv`는 원본도), `rm`, `touch`, `truncate`, `dd of=`, `ln`(만드는 쪽).
  - PowerShell: `Set-Content`, `Add-Content`, `Clear-Content`, `Out-File`, `Tee-Object`, `Export-Csv`, `New-Item`, `Remove-Item`, `Copy-Item`, `Move-Item`, `Rename-Item`과 흔한 별칭(`ni`, `ri`, `rm`, `del`, `cp`, `copy`, `mv`, `move`, `ren`, `ac`). `-Path`·`-LiteralPath`·`-FilePath`·`-Destination` 값과 첫 위치 인자.
- 경로 해석: 그 명령 시점의 작업 폴더(`cwd_at`) 기준. `$`, 백틱, `*`가 든 대상은 정하지 않고 `unresolved`로 센다.
- 대상이 이미 있는 폴더이면 그 안의 파일을 쓰는 것으로 보고 판정한다(`rm -r src` 같은 경우).
- 인식하지 않는 것(문서화): 스크립트나 프로그램 내부의 쓰기(`python x.py`, `node`, `git`, 빌드 도구), heredoc으로 넘긴 코드, 별칭과 함수, 변수로 만든 경로.

### 2. 판정 연결 (`on_pre`의 셸 분기)
- 추출한 대상 중 `ignored_path`가 아닌 것마다 `in_approved_scope`로 범위를 본다.
- 범위 밖 대상이 있으면: warn은 대상마다 `observe_authz`로 한 줄 기록하고 그대로 실행한다. enforce는 `REASON_AUTHZ`로 거부하고 대상 파일 이름을 알려 준다.
- `unresolved`는 거부 사유가 아니다(알 수 없는 것을 막으면 정상 명령이 대부분 막힌다). enforce에서 관측 기록에 `unresolved` 사유로 한 줄 남긴다.
- 추출이나 판정 중 예외가 나면: warn은 무시하고 실행(지금 동작 유지), enforce는 거부(닫힌 쪽).
- 테스트 파일 삭제 확인 등 기존 흐름은 그대로 둔다.

### 3. settings.json
- `discipline.py pre`와 `post`의 matcher에 `NotebookEdit`를 더한다(두 줄, 다른 값은 그대로).

### 4. 문서
- CLAUDE.md §2의 "shell writes are not pre-checked yet"를 "셸 쓰기는 명령에서 읽어 낼 수 있는 대상만 사전 판정한다(최선 노력)"로 고친다.
- 한계 목록은 `hooks/shellwrites.py`의 모듈 설명과 이 계획에 둔다.

## 위험
- **완전한 차단이 아니다.** 스크립트·프로그램 내부의 쓰기, 변수로 만든 경로, heredoc 코드는 사전 판정을 거치지 않는다. 이 경우는 Stop 검사(저장소 안)만 남고, git 밖 경로는 보이지 않는다. 그 부분은 P0-08(권한 설정)의 몫이다.

- 기본 모드가 warn이라 이 작업 뒤에도 실제 거부는 일어나지 않는다. 강제 전환은 P0-06과 같은 스위치로 관측 뒤에 한다.
- settings.json 변경은 실행 중인 세션에 바로 반영된다. 바꾸기 전 내용은 git에 있다(되돌리기는 revert).
