## Context
세션이 끝날 때 무엇을 하다 멈췄는지 남기는 장치가 없다. 다음 세션은 git 상태와 계획 파일만 보고 추측한다. 세션이 창을 닫거나 오류로 끝났는지도 알 수 없다.

목표: 세션이 끝날 때 작업 상태를 작은 파일로 남기고(handoff), 같은 프로젝트의 다음 세션 시작 때 그 내용을 알려 준다. **handoff는 상태만 전달한다. 승인이나 권한은 기록하지도 복원하지도 않는다**(마스터 "목표 아키텍처").

## 확인한 사실 (`tests/_baseline/2026-11-11-p0-02.md`)
- SessionEnd hook은 실제로 발생한다(실측, `-p` 실행). 입력 키: cwd, hook_event_name, prompt_id, reason, session_id, transcript_path. 차단할 수 없고 기본 제한 시간은 1.5초다(문서).
- SessionStart의 `source`는 startup, resume, clear, compact, fork다. `--resume`은 session_id를 유지한다(실측).
- 따라서 handoff는 가볍게 만들어야 하고, "handoff 없이 끝난 세션"을 다음 시작 때 알아내는 경로가 필요하다(같은 문서의 결론).
- `hooks/session_context.py`가 SessionStart에서 git 상태와 계획을 주입한다. git 조회 도우미(`git`, `read_git`)와 계획 읽기(`read_plans`)가 있다.
- `~/.claude/state/` 폴더가 있고 git에서 제외된다.
- `tests/final_check.py`(게이트 밖, 수동 점검용)에 settings의 hook 표가 있다.

## 설계
### 1. 기록 (새 스크립트 `hooks/handoff.py`, SessionEnd에서 실행)
- 순수 함수 `build_handoff(payload, git, plan) -> dict`: 허용된 필드만 담는다.
  - `v`, `at`, `session_id`, `reason`, `git_root`, `branch`, `head`(커밋 해시 앞 12자), `dirty`(변경 파일 수), `plan`(주 계획 경로), `next_step`(첫 미체크 단계, 200자까지), `open_steps`(미체크 수)
  - 승인, 범위, task 권한, 프롬프트 내용, 파일 내용은 넣지 않는다. 허용 목록에 없는 키는 저장하지 않는다.
- 저장 위치: `~/.claude/state/handoff/<저장소 경로의 해시>.json`(환경 변수 `CLAUDE_HANDOFF_HOME`으로 바꿀 수 있다, 테스트용). 임시 파일에 쓴 뒤 교체한다.
- 시간: git 조회마다 1초 제한. 조회가 실패하거나 늦으면 그 필드를 비운 채 저장한다. 저장소 밖에서 끝난 세션은 기록하지 않는다.
- 실패해도 종료 코드는 0이다(세션 종료를 방해하지 않는다). 실패는 stderr 한 줄.

### 2. 열린 세션 표시
- SessionStart(`session_context.py`)가 같은 폴더에 `<해시>.open.json`(`session_id`, `at`)을 쓴다. SessionEnd가 handoff를 쓰면서 자기 세션의 표시를 지운다.
- 다음 시작 때 **다른 session_id**의 표시가 남아 있으면 "이전 세션(시각)이 종료 기록 없이 끝났거나 아직 실행 중"이라고 알린다. 표시가 14일보다 오래됐으면 지운다.

### 3. 복원 (SessionStart 주입에 한 절 추가)
- 그 저장소의 handoff가 있고 14일 이내이면 "## 지난 세션 종료 기록" 절을 붙인다: 종료 시각과 사유, 그때의 브랜치·커밋·변경 파일 수, 계획과 다음 단계.
- 지금 상태와 다르면 표시한다: 커밋이 달라짐, 브랜치가 달라짐. "기록은 참고용이며 현재 git 상태와 계획 파일이 기준"이라는 문구를 붙인다.
- "이 기록은 승인을 복원하지 않는다. 작업을 이어가려면 사용자가 `task:<id>`를 지정하거나 새로 승인한다"를 명시한다.
- 절의 길이는 600자 이하. 전체 4000자 한도는 그대로다(P0-09의 안내 줄과 같은 방식으로, 머리말·git·주 계획 제목이 남긴 공간 안에서만 싣는다).
- handoff 파일이 손상됐거나 형식이 다르면 무시한다.

### 4. 설정
- `settings.json`에 `SessionEnd` hook을 등록한다: `handoff.py end`, timeout 5.
- `tests/final_check.py`의 hook 표에 `SessionEnd`를 더한다.

## 위험
- SessionEnd는 창을 강제로 닫거나 프로세스가 죽으면 실행되지 않는다. 그 경우는 열린 세션 표시로만 드러난다.
- 같은 프로젝트에서 세션을 여러 개 동시에 쓰면 서로의 표시를 "종료 기록 없이 끝났거나 실행 중"으로 본다(문구에 두 가능성을 모두 적는다). handoff는 마지막에 끝난 세션의 것만 남는다.
- handoff의 `next_step`은 계획 파일의 문구를 그대로 옮긴다. 계획 파일에 비밀정보를 적지 않는다는 기존 규칙에 기대며, 마스킹은 P1-09에서 다룬다.
- settings.json 변경은 실행 중인 세션에 바로 반영된다. 되돌리기는 git revert다.
