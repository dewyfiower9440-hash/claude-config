## Context
`/implement`는 계획을 다시 시작할 때 계획 파일의 체크박스와 `git log`만 본다(`skills/implement/SKILL.md` 0절). 그 작업이 어느 검증 상태까지 갔는지(구현만 됨, 게이트 통과, CI 통과, 실패)는 P1-01의 원장에 있지만 사람이 읽을 방법이 없다. 세션 시작 안내가 진행 중인 계획의 원장 상태를 보여 주기는 하나(P1-06), 세션 중간에 `/implement`를 부를 때는 보이지 않는다. 이 항목은 원장을 읽어 보여 주는 명령 하나와, `/implement`가 그것을 쓰는 절차 한 단락을 더한다. 원장은 기록일 뿐이다: 승인이나 검증의 근거로 쓰지 않는다는 점을 명령의 출력과 skill 문서에 적는다.

## 확인한 사실
- `hooks/ledger.py`에는 읽는 함수가 있다: `read(root) -> (entries, problem)`은 원장이 없거나 읽을 수 없어도 예외를 내지 않고, 변조·잘림·비밀 없음은 `problem` 문구로 준다(`ledger.py:290`). `latest(entries)`는 작업별 마지막 기록이다(`ledger.py:201`). 기록의 키는 `at`, `task`, `state`, `content`, `review`, `roots` 등이다(`FIELDS`, `ledger.py:52`).
- 명령행 진입점은 없다. 세션 시작 안내의 문구는 `session_context.ledger_notes`가 만든다(`hooks/session_context.py:174`). 상태 이름의 한국어 표기 `LEDGER_STATE`도 거기 있다.
- `/implement`의 0절은 계획 파일, `git log --oneline -10`, 작업 트리 확인을 요구한다.

## 설계
`hooks/ledger.py`에 추가:
- 순수 함수 `show_lines(entries, problem, task, now) -> list[str]`
  - `task`가 있으면 그 작업의 마지막 기록 한 줄: `<task>: <상태> (리뷰 <판정>), <시각, 며칠 전>, 내용 <content>`. 없으면 "기록 없음".
  - `task`가 없으면 작업별 마지막 기록을 최근 순으로 10개까지.
  - `problem`이 있으면 첫 줄에 "경고: 이 원장은 온전하지 않습니다(…). 아래 내용을 믿지 말고 게이트와 CI를 다시 확인하세요."
  - 마지막 줄은 항상 "원장은 기록입니다. 승인이나 검증의 근거가 아닙니다: 상태가 LOCALLY_VERIFIED여도 그 뒤에 내용이 바뀌었으면 게이트를 다시 실행하세요."
- `main(argv)`: `python -I hooks/ledger.py show [--task ID] [--root DIR]`. `--root`가 없으면 현재 폴더의 git 저장소 맨 위(`git rev-parse --show-toplevel`, 시간 제한 5초). 종료 코드: 0 기록을 보여 줌, 1 기록 없음, 2 잘못된 입력(저장소가 아님 등), 3 원장이 온전하지 않음(내용은 보여 주되 경고와 함께).
- 읽기만 한다. 원장 파일도 비밀 파일도 만들지 않는다(`read`는 `secret(create=False)`를 쓴다).

`skills/implement/SKILL.md` 0절에 한 항목:
- 계획의 `task`로 `python -I ~/.claude/hooks/ledger.py show --task <id>`를 실행해 마지막 검증 상태를 본다. 그것은 참고다: 체크박스와 원장이 어긋나면(예: 단계는 모두 체크됐는데 원장은 BLOCKED) 보고에 적고 게이트부터 다시 실행한다. 원장의 상태를 근거로 게이트·리뷰·승인을 건너뛰지 않는다.
