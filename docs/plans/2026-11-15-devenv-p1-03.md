## Context
CLAUDE.md §3은 "새 동작에는 테스트가 따른다"고 정하지만, 코드만 고치고 테스트를 건드리지 않은 턴을 알려 주는 장치는 없다. 게이트가 통과하면 그대로 끝난다. 턴이 끝날 때 "구현 파일은 바뀌었는데 테스트 파일은 하나도 바뀌지 않았다"를 가려, 다음 입력 때 한 번 알려 준다. 판정은 거칠다(순수 리팩터링, 설정성 코드도 걸린다). 그래서 막지 않고 알리기만 하며, 얼마나 자주 걸리는지 기록한다.

## 확인한 사실
- Stop 때 `refresh_content`가 이번 턴에 바뀐 파일 목록을 만든다(`state["turn_changes"]`, 모든 도구의 변경 포함, `hooks/discipline.py`의 `refresh_content`). 저장소 루트 목록은 `state["repos"]`의 키다.
- 코드 파일 판별은 `CODE_EXT`(`:84`), 테스트 파일 판별은 `TEST_PATH`(`:182`, `tests/`·`test_*.py`·`*.test.ts` 등)가 이미 있다. 경로는 프로젝트 안의 상대 경로로 분류해야 한다(상위 폴더 이름에 `tests`가 있다고 전부 테스트로 보면 안 된다 — `review_triggers`의 주석).
- Stop hook의 출력은 "막는다" 하나뿐이다. 막지 않고 모델에게 알리려면 다음 프롬프트의 추가 문맥으로 넣는다(`on_prompt`의 `told` → `emit_prompt_context`, 프로젝트 전환 안내가 쓰는 방식).
- 편집 도구로 고친 코드 파일은 세션 동안 `state["dirty"][root]["files"]`에 쌓인다.

## 설계
### 1. 순수 판정 `test_gap(turn_changes, session_files, tops) -> list[str]`
- 이번 턴에 바뀐 파일 중 코드 파일(`CODE_EXT`)이면서 테스트 경로가 아닌 것이 "구현 파일"이다.
- 이번 턴에 바뀐 파일이나 이 세션에서 편집한 파일 중 테스트 경로가 하나라도 있으면 빈 목록(누락 아님).
- 구현 파일이 있고 테스트가 없으면 구현 파일들을 돌려준다. 테스트 경로 판별은 저장소 루트 기준 상대 경로로 한다.

### 2. Stop: 기록만 한다
- `refresh_content` 뒤에 `note_test_gap(state)`를 부른다. 누락이면 `state["test_gap_note"]`에 안내문(파일 이름 3개까지, 전체 개수)을 넣고, 관측 기록 한 줄(`test-gap-observe.jsonl`: 시각, 구현 파일 수, 경로 없음)을 남긴다. 누락이 아니면 안내문을 비운다.
- **Stop의 판정과 출력은 바꾸지 않는다.** 실패는 로그만 남긴다.

### 3. 다음 프롬프트: 한 번 알린다
- `on_prompt`가 `test_gap_note`가 있으면 추가 문맥에 붙이고 비운다(subagent 결과 전달 같은 relay 프롬프트에서는 그대로 둔다).
- 문구: 사실과 선택지만 적는다 — "지난 턴에 구현 파일 N개가 바뀌었고 테스트 파일은 바뀌지 않았다. 테스트가 필요한 변경이면 추가하고, 필요 없으면 보고에 그 이유를 적어라."

### 검토한 대안
| 방식 | 판단 |
|---|---|
| A. Stop에서 기록, 다음 프롬프트에서 한 번 안내 | **채택** |
| B. Stop에서 막는다 | 기각: 판정이 거칠어 오탐이 많을 것이고, 범위 정의가 "막지 않음"이다 |
| C. 사용자 화면에만 경고(`systemMessage`) | 기각: 모델이 보지 못해 행동이 바뀌지 않는다 |
