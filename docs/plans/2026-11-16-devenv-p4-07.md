## Context
MCP 도구의 권한이 도구별로 분류돼 있지 않다. github MCP는 쓰기 도구 일부만 확인 대상이고, playwright는 서버 통째로 허용돼 있어 페이지를 조작하거나 코드를 실행하는 도구도 확인 없이 돈다. 이 항목은 (1) 서버가 스스로 붙인 읽기 전용 표시를 근거로 도구 목록을 저장소에 기록하고, (2) 쓰기 도구가 모두 확인을 거치도록 `settings.json`의 ask 목록을 보강하고, (3) 그 상태가 깨지면 게이트가 실패하게 한다. 새 MCP 서버나 권한 확대는 없다(확인이 늘어날 뿐이다).

## 사용자 결정 (2026-11-16, 하나씩 물어 받은 답)
1. github MCP: 목록에 없는 쓰기 도구 11개를 **모두 ask에 추가**.
2. playwright MCP: **조작 도구만 ask로**. 여는 것·읽는 것 14개는 그대로 허용, 페이지를 바꾸거나 코드를 실행하는 12개는 확인(그중 2개는 이미 ask).
3. push: **P4 항목마다 push하고 CI 확인**.

## 확인한 사실 (2026-11-16, 두 서버에 `tools/list`만 보내 읽음. 도구는 하나도 호출하지 않았다)
- **github MCP**(v2.1.0): 도구 48개. 서버의 `readOnlyHint`가 참인 것 30개, 아닌 것 18개.
  - 이미 ask인 7개: `push_files`, `create_or_update_file`, `delete_file`, `merge_pull_request`, `update_pull_request_branch`, `create_pull_request`, `actions_run_trigger`.
  - **목록에 없는 11개**: `add_comment_to_pending_review`, `add_issue_comment`, `add_reply_to_pull_request_comment`, `assign_copilot_to_issue`, `create_branch`, `issue_write`, `pull_request_review_write`, `request_copilot_review`, `sub_issue_write`, `update_issue_comment`, `update_pull_request`.
  - deny의 `delete_repository`는 서버가 내놓지 않는 도구다(방어용으로 남긴다).
- **playwright MCP**(`@playwright/mcp` 0.0.81): 도구 26개. 읽기 전용 표시 8개(`browser_console_messages`, `browser_find`, `browser_network_request`, `browser_network_requests`, `browser_snapshot`, `browser_take_screenshot`, `browser_wait_for`, `browser_webmcp_list`), 나머지 18개는 서버가 모두 `destructiveHint`로 표시한다(페이지 열기까지 포함).
  - 이미 ask인 2개: `browser_run_code_unsafe`, `browser_file_upload`.
- `settings.json`의 MCP 규칙: allow `mcp__context7`, `mcp__playwright`(서버 통째), ask 9개, deny 1개. 서버 통째 허용과 도구별 ask가 함께 있을 때 ask가 우선한다는 전제로 이미 2개가 그렇게 설정돼 있다. 이 우선순위는 구현 단계에서 공식 문서로 확인한다(지금은 미확인).
- 기존 점검 스크립트 `tests/smoke_gh_mcp.py`, `tests/smoke_playwright_mcp.py`가 같은 방식(`tools/list`)으로 서버를 읽는다. 게이트에는 들어 있지 않다(CI에 서버가 없다).
- claude.ai 커넥터(Docs, Drive, Calendar, Gmail)와 context7은 원격 서버라 표시를 읽지 않았다. settings에 도구별 규칙이 없다.

## 설계
1. **도구 목록의 기록** `tests/mcp_tools.json`: 서버별 도구 이름과 서버가 준 표시(`readOnly`, `destructive`), 읽은 날짜와 서버 버전. github·playwright는 `tools/list`의 결과 그대로다. 손으로 고치지 않는다.
2. **다시 읽는 스크립트** `tests/mcp_inventory.py`(게이트 밖, 기존 smoke 스크립트와 같은 자리): 두 서버에 `tools/list`를 보내 JSON을 출력하고, `--check`면 기록과 비교해 달라진 도구를 알린다(서버를 올린 뒤 실행한다). 도구를 호출하지 않는다.
3. **게이트 안의 대조 테스트** `tests/test_mcp_permissions.py`(네트워크·서버 없이 `settings.json`과 기록만 읽는다):
   - github: 읽기 전용 표시가 없는 도구는 모두 ask나 deny에 있다.
   - playwright: 읽기 전용 표시가 없는 도구는 ask에 있거나, 테스트에 이름과 이유를 적어 둔 "여는 것·보는 것" 6개(`browser_navigate`, `browser_navigate_back`, `browser_tabs`, `browser_hover`, `browser_resize`, `browser_close`) 중 하나다. 그 6개 목록이 늘면 테스트의 그 줄을 고쳐야 하므로 변경이 리뷰에 드러난다.
   - 도구 하나를 allow하는 규칙은 읽기 전용 표시가 있는 도구에만 허용한다. 서버 통째 allow는 지금의 둘(`context7`, `playwright`)뿐이다.
   - ask·allow 규칙이 기록에 없는 도구 이름을 가리키면 실패한다(낡은 규칙). deny는 예외다(없는 도구를 막아 두는 것은 해가 없다).
   - 기록의 도구 수가 0이 아니고 형식이 맞다.
4. **`settings.json`**: ask에 github 11개와 playwright 10개(`browser_click`, `browser_type`, `browser_fill_form`, `browser_press_key`, `browser_select_option`, `browser_drag`, `browser_drop`, `browser_evaluate`, `browser_handle_dialog`, `browser_webmcp_call`)를 더한다. allow·deny와 그 밖의 설정은 건드리지 않는다. 변경 전 사본을 `backups/settings-2026-11-16.json`에 둔다(git이 무시하는 폴더).

순서: 기록과 테스트를 먼저 쓰고(테스트는 21개 도구 때문에 실패한다) → 사본 → settings 변경 → 테스트 통과.
