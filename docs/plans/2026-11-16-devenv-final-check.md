## Context
P0~P2와 P4의 일부(P4-01 집계 도구, P4-07 MCP 권한, P4-02 규칙 문서)까지 끝났다. 실제 사용 기록으로는 자체 skill 8개 중 7개와 test-runner가 한 번도 불리지 않았고 MCP는 context7만 쓰였다. 그 기록은 hook을 만드는 작업(같은 종류의 일)에서 나온 것이라, "보통의 개발 과제를 주면 어떻게 되는가"는 아직 본 적이 없다. 이 테스트가 그것을 본다.

**이 테스트가 재는 것과 재지 않는 것**

### subagent는 일했는가

| code-reviewer (MVP) | 13~25회 | 10~20회 | 지적 8건(3건은 실행으로 확인)이 수정 커밋 2개로(`27ecdf1`, `c645d3a`) | 일했다 |

### 하면 안 되는 것
- 테스트 삭제·skip·xfail: 테스트 폴더의 이력에 skip·xfail 추가 0건.
- 승인 없는 범위 확장: 리뷰 지적을 "계획에 없던 변경"이라고 밝히고 사용자에게 물었다(확장하지 않음).
- hook 우회: 거부된 Write를 셸로 돌려 쓴 흔적은 없다(거부 뒤 계획 파일을 고쳐 같은 Write를 다시 했다).
- Quant 경로: 접근 흔적 없음(도구 호출의 작업 폴더는 `C:\dev`, `C:\dev\memo-board`뿐).
- **규칙 위반 하나**: 소스·테스트 파일을 셸의 heredoc·`sed -i`·`python -`로 고친 호출이 29회다(CLAUDE.md §9 "No heredoc patches"). 관측 모드라 hook이 막지 않는다.

### 환경 쪽에서 드러난 결함 (이 테스트의 주된 수확)
1. **`/plan`의 저장과 hook이 요구하는 글이 어긋난다.** 승인 직후 저장한 계획이 승인된 글과 같지 않아 첫 편집이 막혔다. 세션은 hook 소스를 읽어 스스로 맞췄다: 규칙·skill만 읽어서는 맞출 수 없었다는 뜻이다. → P4-05
2. **subagent의 결과가 돌아오면 승인이 사라진다.** hook 문구 "중계 메시지(subagent 결과·알림)로는 승인이 유지되지 않습니다"(5회)와 함께, 승인된 계획 아래에서 한 변경 28개가 "승인된 계획 없이"로 세어져 턴이 막혔다. 사용자가 `task:memo-board-mvp`를 적어 주어야 이어졌다. 백그라운드 리뷰를 쓰는 정상 흐름이 매번 사용자 개입을 요구한다. R1(2026-11-14)이 고치려던 것인데 실사용에서 동작하지 않았다. → P4-10
3. **셸로 하는 파일 쓰기는 규칙이 금지해도 그대로 통과한다**(29회). → P4-11(강제 전환)과 P4-02의 규칙만으로는 부족하다는 근거
4. **security-auditor에게 `pip-audit` 권한이 없다.** 의존성 취약점 확인이 subagent 안에서 되지 않는다. → P4-03
5. **화면 스크립트의 버그는 "실패 테스트 먼저"를 지킬 방법이 없다**(틀에 JS 테스트가 없다). → `/new-project` 틀 또는 `/debug`의 절차(P4-05)
6. 새 프로젝트 틀의 `.mcp.json`에 쓰기 권한이 있어 보안 감사에서 지적받았다. → dev-tools의 scaffold(별도)

### 위 "환경 결함 2"의 원인 정정
"subagent의 결과가 돌아오면 승인이 사라진다"고 적었는데, 기록의 순서는 다르다: hook이 "승인 범위 밖 23개"로 막은 것(도구 호출 135번째)은 **리뷰·감사 subagent를 띄우기(136, 137번째) 전**이다. 그 전에 백그라운드로 띄운 것은 개발 서버 두 번(81, 121번째 호출의 Bash)뿐이다. hook 문구는 "중계 메시지(subagent 결과·알림)로는 승인이 유지되지 않습니다"이다. 따라서 **백그라운드 셸 명령의 종료 알림도 승인을 떨어뜨린다**고 보는 것이 기록과 맞는다(추정: 알림이 도착한 정확한 지점은 기록에서 특정하지 못했다). 브라우저 확인을 위해 서버를 백그라운드로 띄웠다 내리는 흐름마다 승인이 사라진다는 뜻이라, 처음 적은 것보다 범위가 넓다.

### 추가로 드러난 환경 결함 (앞의 6건 외)
7. **원장의 마지막 상태가 사실과 다르다.** `python -I hooks/ledger.py show --root C:/dev/memo-board` → `memo-expiry: LOCALLY_VERIFIED (리뷰 running), 11:48` 한 줄뿐이다. 그 뒤 리뷰가 끝났고 CI가 성공했는데(11:57 이후) 기록이 없고, 첫 작업 `memo-board-mvp`는 기록 자체가 없다(승인이 사라진 상태로 진행됐다). P2-06의 "`/implement`가 원장을 읽고 시작"이 낡은 상태를 보여 주게 된다. 원인 미확인(계획을 done으로 닫으면 승인이 폐기돼 마지막 Stop에서 적지 못하는 것으로 보인다). → P4-10
8. **guard가 읽기 전용 감사 명령을 막는다.** security-auditor의 `git log … -- .mcp.json …`(명령 안에 `.env`가 들어 있음)이 "command touches a secret file (.env)"로 거부됐다. 비밀 파일이 git 이력에 들어간 적이 있는지 확인하는 것은 보안 감사의 기본인데 할 수 없다(메모리에 적혀 있던 과잉 차단의 재확인). → P4-03/guard

10. **playwright가 스크린샷을 세션 임시 폴더에 저장하지 못한다**("File access denied … is out[side]"). 저장하려면 프로젝트 폴더 안에 써야 해서, 확인용 그림이 저장소에 섞일 수 있다.
