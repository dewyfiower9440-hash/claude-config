# devenv P2-01·P2-03: 턴의 위험 점수와 대안 비교 안내 (관측만)

- 단계 계획: `docs/plans/2026-11-15-devenv-p2.md` 단계 2, 마스터 계획 32번
- 저장 위치: `docs/plans/2026-11-15-devenv-p2-01.md`
- 승인 근거: 사용자 지시 2026-11-15 "개발환경 고도화 작업 이어서 계속해"(상시 승인)

## Context
변경의 위험은 지금 "파일 수" 하나로만 본다. hook·CI·의존성 잠금을 건드리는 변경과 문서 변경이 같게 취급된다. 이 항목은 한 턴의 변경에 점수를 매겨 **기록**하고, 점수가 높은데 진행 중인 계획에 대안 비교가 없으면 다음 프롬프트에 한 번 **알린다.** 막지 않는다. 채택 여부는 P3 평가로 정한다.

## 확인한 사실
- Stop에서 `refresh_content`가 `state["turn_changes"]`(이번 턴에 내용이 바뀐 파일의 절대 경로)를 만든다(`hooks/discipline.py:2710`). `state["repos"]`는 추적 중인 저장소 루트다.
- Edit·Write로 바뀐 줄 수는 `state["dirty"][root]["lines"][path]`에 쌓인다(`mark_dirty`, `discipline.py:1922`). 세션 누적이고 셸로 바꾼 줄은 없다. 그래서 줄 수는 "이번 턴에 바뀐 파일의 세션 누적 줄 수"라는 거친 값이다.
- P1-03의 방식: Stop에서 순수 함수로 판정 → `state["test_gap_note"]`에 문구 → 다음 사용자 프롬프트에서 한 번 전달(relay 프롬프트는 건너뜀, `discipline.py:2296`) → 관측 파일에 숫자만 한 줄(`note_test_gap`, `discipline.py:3271`). 실패는 삼키지 않고 기록하며 Stop 판정에 영향이 없다.
- 승인 상태 `state["approval"]`에는 `task_id`와 `base`가 있다(`discipline.py:1770`). 계획 본문은 `base/docs/plans/*.md`에서 `plan_task(text)`로 찾을 수 있다.
- `_repo_place(path, tops)`가 (저장소, 저장소 안 경로)를 주고 `is_test_file`이 테스트 파일을 가린다(`discipline.py:3218`, `3227`).

## 설계
새 모듈 `hooks/risk.py`(순수 함수만, I/O 없음):
- `kind(rel: str, is_test: bool) -> str`: 저장소 안 경로(슬래시 구분)의 종류.
  `guard`(자동화가 작업을 지키는 파일: `hooks/**`, `.claude/**`, `.husky/**`, `.pre-commit-config.yaml`, `settings.json`), `ci`(`.github/workflows/**`, `.gitlab-ci.yml`, `azure-pipelines.yml`), `schema`(`migrations/**`, `*.sql`, `schema.*`), `deps`(잠금 파일과 의존성 선언: `uv.lock`, `pnpm-lock.yaml`, `package-lock.json`, `pyproject.toml`, `package.json`, `requirements*.txt`, `Cargo.*`, `go.mod`, `go.sum`), `test`, `docs`(`.md`, `.rst`, `.txt`, `docs/**`), `code`(`CODE_EXT`), `config`(그 밖의 `.toml|.yaml|.yml|.json|.ini|.cfg|.env.example`, `Dockerfile`), `other`. 위에서부터 먼저 맞는 것.
- `Risk`(frozen dataclass): `score: int`, `kinds: dict[str, int]`(종류별 파일 수), `files: int`, `lines: int`, `repos: int`.
- `assess(kinds: Sequence[str], lines: int, repos: int) -> Risk`. 점수 = 나온 종류들의 가중치 합 + 크기 항.
  - 가중치(초기 값): guard 5, ci 5, schema 5, deps 4, code 2, config 2, test 1, other 1, docs 0.
  - 크기: 파일 3~5개 +1, 6~10개 +2, 11개 이상 +3. 줄 50~199 +1, 200~499 +2, 500 이상 +3. 저장소가 2개 이상이면 추가 저장소마다 +2.
- `compares_alternatives(plan_text: str) -> bool`: 제목 줄(`#`)이나 표의 머리 줄에 "대안", "옵션", "선택지", "비교", "alternative", "option", "trade-off" 중 하나가 있으면 True.
- `ADVICE_AT = 8`(초기 값), `threshold(env_value) -> int`: 환경 변수 `CLAUDE_RISK_ADVICE_AT`가 양의 정수면 그 값.

`hooks/discipline.py`:
- `note_risk(state)`: `on_stop`에서 `note_test_gap` 다음에 호출. `CLAUDE_RISK_SCORE=0`이면 아무것도 하지 않는다(상태도 건드리지 않음). `turn_changes`가 비면 문구를 비우고 끝. 아니면 점수를 계산해 턴당 한 번 `risk-observe.jsonl`에 `{"at", "score", "kinds", "files", "lines", "repos", "advised"}`를 쓴다(경로·이름 없음). 점수가 기준 이상이고, 진행 중인 승인 작업의 계획 파일 중 대안 비교가 있는 것이 없으면 `state["risk_note"]`에 문구를 둔다.
- 문구: "[discipline] 지난 턴의 변경은 위험 점수 N입니다(구성). 진행 중인 계획에 대안 비교가 없습니다. 되돌리기 어려운 변경이면 대안 2~3개와 trade-off를 계획에 적고 진행하세요. (알림이며 차단이 아닙니다.)" 300자 한도.
- `on_prompt`: `test_gap_note`와 같은 자리에서 `risk_note`를 한 번 전달하고 비운다(relay는 건너뜀).
- 상태 기본값에 `risk_note`, `risk_turn` 추가.
- 계획 본문 읽기는 점수가 기준 이상일 때만 한다(파일 몇 개, Stop에서만).

prompt hook에는 문자열 하나를 덧붙이는 것 외의 작업을 넣지 않는다.

## 테스트 (`tests/test_risk.py`, 먼저 작성해 실패 확인)
| 묶음 | 내용 |
|---|---|
| 순수: 종류 | 경로별 종류(hook, workflow, 잠금 파일, migration, 테스트, 문서, 코드, 설정, 기타), 대소문자, 역슬래시 경로 |
| 순수: 점수 | 문서만 = 0, 코드 1개 = 2, hook 1개 = 5, hook + CI + 잠금 = 14, 크기 경계(2/3, 5/6, 10/11개; 49/50, 199/200, 499/500줄), 저장소 2개 +2, 빈 입력 = 0, 이상한 값에 오류 없음 |
| 순수: 대안 | 제목·표 머리에 낱말이 있으면 True, 본문 문장에만 있으면 False, 빈 글 False |
| 순수: 기준 | 변수 없음·잘못된 값·0·음수 → 기본 8, "5" → 5 |
| hook: 낮은 점수 | 코드 1개 변경: 관측 한 줄(score 2, advised false), 다음 프롬프트에 안내 없음, Stop 판정은 기준 세션과 같음 |
| hook: 높은 점수 | hook 파일 + workflow + 잠금 파일 변경, 계획 없음: 안내 한 번(다음 프롬프트), 그 다음에는 없음, 관측 줄에 경로·파일 이름 없음 |
| hook: relay | relay 프롬프트는 안내를 쓰지 않고 사용자의 다음 프롬프트가 받음 |
| hook: 끔 | `CLAUDE_RISK_SCORE=0`: 관측 파일 없음, 안내 없음 |
| hook: 기록 실패 | 관측 파일을 쓸 수 없어도 Stop 판정이 같고 안내는 나옴 |
| hook: 턴당 한 번 | 한 턴에 Stop이 두 번 와도 관측은 한 줄 |

"승인된 계획에 대안 비교가 있으면 안내 없음"은 순수 함수 `advice_needed(score, at, plan_texts)`로 나눠 순수 테스트로 확인한다(hook 수준에서 승인을 만드는 것은 승인 저장소가 필요해 이 테스트에서 하지 않는다).
